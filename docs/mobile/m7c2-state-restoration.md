# M7C2 secure state and response-loss recovery

Canonical create operations use one secure-storage bundle at `masari_canonical_operation_v1`. Bundle schema version 2 stores only operation type, role scope, authenticated actor ID, random idempotency key, normalized exact payload, deterministic change-detection fingerprint, creation time, and route-version ID. It is never stored in preferences or logs.

Before sending a new operation, the client revalidates capability/current-route eligibility, synchronously fences duplicate taps, persists the bundle, and confirms secure persistence. Only then may it send. Timeout, connection loss, HTTP 502/503, `transaction_retry_required`, and ambiguous idempotency responses retain the exact bundle. A recreated screen restores only tentative selections for the same authenticated actor; a different account cannot inspect or replay the payload. An identical retry reuses the same key. A changed payload or different operation is blocked while the prior outcome is unresolved and cannot overwrite it.

Success or idempotent replay success does not delete the bundle inside the network runner. Passenger and merchant results delete it only when the confirmed result has been represented and the user acknowledges leaving that result. Driver creation deletes it only after the owner detail read reconciles the exact returned availability fields. Definitively terminal, uncommitted validation/authorization/feature/route failures clear it; ambiguous idempotency conflict does not.

Explicit logout, logout-all, current-session revocation, password/security-version change, suspension, disablement, and role change preserve an unresolved encrypted bundle while clearing authentication. Reauthentication as the same actor is required before recovery; another actor is blocked. Access-token expiry continues through the existing single-flight refresh coordinator, so its authenticated retry retains the same request closure and idempotency header.

The 24-hour server idempotency window is a recovery boundary, not a client deletion timer. At or beyond the boundary, on clock rollback beyond five minutes, on unknown/corrupt bundle schema, or when the bundle cannot be safely decoded, the secure entry is quarantined and submission remains blocked. M7C2 has no owner-history endpoint, so resolution after that boundary is support-assisted; the application never silently discards the only replay key and never creates a replacement operation automatically.

Merchant parcel payloads exist in secure storage only while an exact atomic replay may be needed and are deleted after confirmed result acknowledgement or a definitively uncommitted terminal failure. Raw keys, payloads, tokens, credentials, coordinates, and personal details are not printed.
