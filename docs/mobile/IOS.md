# Masari iOS target

Status: the iOS project exists and is configured statically. It has **not** been
built or run on any Apple toolchain by the author (developed on Windows). The
first real evidence is the new `ios-build` job in `.github/workflows/ci-mobile.yml`.

## What is done

- `apps/mobile/ios/` generated by `flutter create --platforms=ios --org ps.masari`
  (Flutter 3.44.6, the version in `.flutter-version`). Plugins are integrated
  through Swift Package Manager, so there is no committed Podfile; Flutter
  creates one on demand only if a plugin still needs CocoaPods.
- Bundle identifier `ps.masari.mobile` (same as the Android `applicationId`);
  tests target `ps.masari.mobile.RunnerTests`.
- Display name `Masari` (English) and `مساري` (Arabic) via `InfoPlist.strings`.
- `CFBundleLocalizations` = `en`, `ar`; both are in the project's `knownRegions`,
  and `Runner/{en,ar}.lproj/InfoPlist.strings` are registered as a variant group
  in `project.pbxproj` so they are bundled. (Hand-edited; Xcode should open it
  cleanly, but check that on the Mac.)
- Usage strings (EN and AR): `NSLocationWhenInUseUsageDescription`,
  `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`.
- Deployment target iOS 14.0 (CI showed `file_picker_darwin` needs at least 14.0; Flutter default is 13.0). The plugins in `pubspec.yaml`
  (`file_picker`, `flutter_secure_storage`, `geolocator`, `google_sign_in`,
  `shared_preferences`) must all support 14.0.
- `ITSAppUsesNonExemptEncryption=false` (HTTPS only, no custom crypto). Revisit if that changes.
- Git hygiene: Pods, `build/`, `xcuserdata`, `*.xcuserstate`, `Flutter/ephemeral`,
  `Generated.xcconfig`, `GeneratedPluginRegistrant.*`, `*.p12`, `*.mobileprovision`,
  `GoogleService-Info.plist` are ignored (root `.gitignore` and `ios/.gitignore`).

## Needs a Mac and/or an Apple Developer account

- Opening `ios/Runner.xcworkspace` in Xcode and running on a simulator/device.
- Signing: set the Team, create the App ID `ps.masari.mobile`, provisioning profiles, certificates.
- Real Google sign-in: create an iOS OAuth client in Google Cloud for the bundle ID, then set the reversed client ID in `Info.plist` and pass `GOOGLE_IOS_CLIENT_ID`.
- Push notifications (if wanted): enable the capability, APNs key, `aps-environment` entitlement. Not configured, and no push plugin is in use today.
- TestFlight / App Store: archive, upload, App Store Connect listing, privacy nutrition labels, review notes.
- App icon and launch screen: the Flutter default assets are still in place.
- Arabic RTL check on device (layout is Flutter-driven, but verify system dialogs and permission prompts).
